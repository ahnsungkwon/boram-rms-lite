# 보람 RMS Lite 0.4.0 — 간결 워크플로 사용 안내

0.4.0 Release 빌드는 경고 0개·오류 0개, 합성 자료 실행 시험은 59개 통과·실패 0개입니다. 배포 ZIP의 TEST_SUMMARY.txt에 해당 패키지의 재검수 결과가 포함됩니다. 실제 업무 폴더와 모든 NAS·한글 입력기 환경까지 검증했다는 의미는 아닙니다.

## 기본 작업

**폴더 열기 → 이미지 확인 → 이름·상태 수정 → 저장하고 다음**

상단 `+ 폴더 선택`으로 이미지 폴더를 엽니다. 폴더마다 작업 탭이 열립니다. 기존 행사 폴더를 선택하면 그 안의 신청서 원본 위치를 찾는 편의 기능은 유지하지만, 상태 저장에 행사/보완 폴더 구분을 요구하지 않습니다.

| 동작 | 결과 |
|---|---|
| 저장하고 다음 / 이름 입력칸에서 Space | 이름과 상태를 함께 저장하고 다음 이미지로 이동합니다. |
| 저장만 / Ctrl+S / 아래쪽 이름·상태 저장 | 이름과 상태를 함께 저장하고 현재 이미지에 머뭅니다. |
| 건너뛰기 / 이전·다음 | 저장하지 않고 이동합니다. 바꾼 입력이 있을 때만 버릴지 확인합니다. |
| 상태 비우기 | 체크와 메모를 비웁니다. 아직 파일은 바뀌지 않으며 저장하면 반영됩니다. |
| 되돌리기 | 이번 실행에서 현재 폴더의 마지막 이름·상태·회전 변경을 되돌립니다. |

검색·메모·체크박스의 Space는 원래 입력/선택 동작입니다. 상태를 먼저 적용한 뒤 이름을 저장하는 절차는 필요하지 않습니다. 잘못된 이름이나 중복 파일명 때문에 저장에 실패하면 입력은 남고, 이유는 하단에 표시됩니다.

## 상태는 표시일 뿐, 폴더를 옮기지 않습니다

카드·CMS·보완·취소·추가 등은 이미지별 Lite 상태로 저장합니다. 상태를 선택해도 이미지 파일이 다른 폴더로 이동하지 않습니다. 보완 사유는 여러 개를 선택할 수 있으며, 서로 배타적인 기타 상태는 한 개만 선택합니다.

리네임은 현재 이미지의 파일명만 바꿉니다. **행사 TXT·구좌별 가공본·jpg 사본·기존 RMS 상태 파일은 자동으로 수정하지 않습니다.** 입력전 구좌 변경은 현재 이미지 이름의 구좌수에 반영하고, 입력후 구좌 변경은 메모에 남기는 구분은 유지합니다.

새 상태는 이미지가 있는 폴더의 `.rmslite` 안에 이미지별 JSON으로 저장합니다. 폴더를 다른 PC로 옮길 때 이 폴더도 함께 복사해야 상태를 유지할 수 있습니다. 폰트나 인증 토큰은 여기에 저장하지 않습니다.

기존 `.boramrms` 로컬 상태는 처음 표시할 때 읽기만 합니다. 새 상태가 있으면 새 상태가 우선합니다. 과거 journal.json이나 백업을 삭제하거나 완료 상태로 강제로 바꾸지 않습니다. 새 작업을 기존 연동에서 분리한 것이며, 과거 업무자료의 손상 여부를 자동 보증하는 것은 아닙니다. 기존 행사 TXT만으로 관리했던 내용은 새 상태에 자동 반영되지 않을 수 있습니다.

## 이름과 이미지 보기

`홍길동`을 먼저 쓰고 `3`을 입력해도 `3홍길동`이 됩니다. `홍길동12`를 붙여 넣은 경우 미리보기와 저장에서는 `12홍길동`으로 정리합니다. 이미 구좌 숫자가 있으면 그 뒤에 추가되므로 구좌를 바꿀 때는 기존 숫자를 선택해 교체합니다.

창 크기·패널 폭·작업 기록 펼침으로 이미지 영역이 달라지면 전체 이미지에 다시 맞춥니다. 단순한 다음·이전 이미지 선택에서는 확대율과 이동 위치를 유지합니다. 휠 확대, 드래그 이동, 맞춤, 좌우 클릭 이동, 패널 분리·복귀는 유지합니다.

## 삭제와 압축

**선택 파일 휴지통 이동**은 폴더 이름과 관계없이 목록에서 선택한 이미지 경로만 확인 후 처리합니다. 선택하지 않은 이미지, jpg 사본, TXT, 상태 기록은 함께 삭제하지 않습니다. 실제 파일이 외부에서 바뀌었거나 읽기 전용이면 해당 작업을 중단합니다. 휴지통 지원을 확인할 수 없는 네트워크 경로는 영구삭제로 전환하지 않습니다. 복구는 Windows 휴지통에서 합니다.

**300KB 미만으로 줄이기**는 현재 검색·필터 결과에 표시된 이미지 전체를 대상으로, 300,000바이트 이상인 파일을 같은 이름과 형식으로 압축합니다. 실행 확인 후 원본에 직접 저장하고 압축 백업은 만들지 않습니다. 이미 작은 파일은 그대로입니다. 압축은 되돌릴 수 없으며 중단해도 이미 완료된 파일은 압축된 상태로 남습니다.

회전은 원본을 저장하며 이전 이미지의 백업을 새 `.rmslite`에 둡니다. 이번 실행의 마지막 회전은 되돌릴 수 있습니다. 뒤이어 파일이 수정됐다면 무조건 덮어쓰지 않습니다.

## 실행과 업데이트

HomePC 런처: `C:\BoramRMS\boram-rms-lite\START_LITE.cmd`

실행 파일: `C:\BoramRMS\boram-rms-lite\dist\BoramRMS_Lite\BoramRms.Lite.exe`

정식 Release가 게시되면 `업데이트 확인 → 업데이트 설치`로 받습니다. 다른 PC에서는 `BoramRMS_Lite_0.4.0_win-x64.zip` 전체를 새 전용 폴더에 풀어 사용합니다. 이전 실행 파일은 소스 수정만으로 교체되지 않으므로 다시 열린 앱에 0.4.0이 표시되는지 확인하세요. 0.3.1에서 저장 실패로 미저장 입력이 남아 업데이트가 막히면 입력 내용을 별도로 복사한 뒤 앱을 닫으며 해당 미저장 입력만 취소하고, 다시 열어 먼저 업데이트하세요. 옛 journal.json이나 백업을 삭제할 필요는 없습니다.

비공개 GitHub 인증은 기존 GitHub CLI 로그인 또는 이 저장소의 Contents 읽기 권한 토큰을 사용합니다. 토큰은 Windows 사용자별로 암호화하며 배포 ZIP과 신청서에 포함하지 않습니다.

기존 전체 RMS와 Lite에서 같은 이미지 폴더를 동시에 수정하지 마세요. 애플리케이션 설치 폴더와 신청서 폴더를 분리하세요. 이번 설계는 로컬 업무 흐름을 단순하게 만드는 것이며 모든 NAS·한글 입력기·전원 차단 상황을 검증했다는 뜻은 아닙니다.

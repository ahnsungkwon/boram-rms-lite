# 보람 RMS Lite 0.3.0 — 사용 안내

## 실행과 화면

HomePC: `C:\BoramRMS\boram-rms-lite\START_LITE.cmd`

실제 실행 파일: `C:\BoramRMS\boram-rms-lite\dist\BoramRMS_Lite\BoramRms.Lite.exe`

다른 Windows x64 PC에서는 Release ZIP 전체를 새 전용 폴더에 풀어 `BoramRMS_Lite\BoramRms.Lite.exe`를 실행합니다. EXE만 옮기지 마세요. .NET 실행 환경을 포함하며 앱 실행에 기존 RMS·Python·Codex·API 키는 필요하지 않습니다. 비공개 GitHub 업데이트에는 별도 읽기 인증이 필요합니다.

흰색 리네임·이미지·목록 패널과 연녹색 강조를 사용합니다. 좌우 폭 조절, 패널 분리·복귀를 지원합니다. 폰트는 PC에 설치된 Pretendard / Malgun Gothic / Segoe UI를 사용하며 폰트 파일을 배포하지 않습니다.

## 폴더와 이미지 이동

`+ 폴더 선택`으로 폴더별 탭을 엽니다. 동일 폴더는 기존 탭을 재사용합니다. 탭 닫기는 파일 삭제가 아닙니다. `작업 복원`은 지난 실행의 탭을 다시 엽니다.

이미지 왼쪽 세로 영역은 이전 이미지, 오른쪽 세로 영역은 다음 이미지입니다. 처음/마지막에서 더 이동하지 않습니다. 휠 확대·드래그 이동이 가능하고, 다음·이전 또는 목록 선택으로 이미지를 바꾸어도 확대율·위치·표시 너비를 유지합니다. 창 크기를 바꿔도 자동 맞춤하지 않습니다. `맞춤` 또는 이미지 트리플클릭으로만 보기 상태를 초기화합니다. 확대 상태는 현재 열린 탭별로 유지하며 앱 종료 후까지 저장하는 기능은 아닙니다.

## Space와 리네임

이름 입력칸에서 `3홍길동`처럼 구좌수+이름을 입력하세요. Space는 이름을 편집했으면 저장하고 다음으로 이동하고, 이름을 편집하지 않았으면 파일 변경 없이 다음으로 이동합니다. 이미지·목록 영역 및 분리창에서도 같은 규칙을 적용합니다. Space를 길게 눌러 여러 장이 연속으로 넘어가지 않도록 제한했습니다.

검색칸·메모칸·체크박스·드롭다운의 Space는 원래 입력과 선택 동작을 유지합니다. 상태 입력이 남아 있으면 먼저 상태를 적용하거나 취소해야 합니다. 한글 입력은 WPF의 IME 키 이벤트를 고려하지만 모든 Windows 한글 입력기 조합을 실제 키보드로 시험한 것은 아닙니다.

`저장하고 다음`, `저장만`, `건너뛰기` 버튼도 제공합니다. 저장 후 이름 입력칸으로 포커스가 돌아옵니다. 파일명 중복이나 원본/가공본의 식별이 불명확하면 임의로 덮어쓰지 않습니다.

## 300KB 미만 직접 압축

왼쪽 아래 **300KB 미만으로 줄이기** 버튼 하나를 사용합니다. 별도 크기·품질·출력 폴더 옵션 창은 없습니다. 대상은 선택한 한 장이 아니라 **현재 검색·필터 결과에 표시된 목록 전체**입니다. 실행 확인창에 대상 개수가 표시됩니다.

**기존 파일명과 형식을 유지하여 바로 덮어씁니다. 원본 사본이나 백업을 새로 만들지 않으며, 이 압축은 ‘되돌리기’로 복구할 수 없습니다.** 이전 버전의 사본 생성 방식과 다르므로 실행 확인 내용을 읽어 주세요.

최종 파일은 300,000바이트 미만을 목표로 합니다. 이미 이보다 작은 이미지는 수정하지 않습니다. JPEG는 품질과 필요시 픽셀 크기를 조절하고, PNG는 형식과 투명도를 유지하며 크기를 조절합니다. 확대·잘라내기는 하지 않습니다. JPEG/PNG 직접 압축을 합성 자료로 검증했으며 BMP/TIFF도 코드상 지원하지만 다양한 실무 파일 검수는 남아 있습니다. 여러 페이지 TIFF·애니메이션 및 지원하지 않는 형식은 제외합니다.

검증된 임시 파일을 만든 뒤 기존 파일을 교체합니다. 손상 이미지, 읽기 전용 파일, 외부 변경, 목표 용량을 달성하지 못한 파일은 변경하지 않습니다. 원자적 교체를 지원하지 않는 네트워크 파일시스템에서는 실패할 수 있으며 안전하지 않은 대체 방식으로 덮어쓰지 않습니다.

하단 `압축 중단` 또는 Esc로 취소합니다. 이미 완료한 파일은 압축된 상태로 남고 미처리 파일은 그대로입니다. 성공/건너뜀/실패 수를 작업 기록에서 확인할 수 있습니다. 압축이 글자의 실무 가독성을 자동 판정하는 것은 아니므로 최초에는 복사본으로 확인하세요.

## 상태·목록·회전

검색, 상태 필터, 정렬, 썸네일, Ctrl/Shift 다중 선택을 제공합니다. CMS/카드, 보완, 취소, 변경 등은 로컬 상태입니다. ERP를 조회하지 않으므로 실제 등록 여부를 추측하지 않습니다. 하단 진행 막대는 선택 위치 기준이며 검수 완료 실적이 아닙니다.

`행사\신청서\[원본]` 구조에서는 리네임·상태 변경 시 원본·구좌별 가공본·카드 메타데이터와 `행사\행사명.txt`를 연결합니다. 일반 폴더는 부모의 TXT를 임의로 수정하지 않습니다. 이미 존재하는 `전화번호_조회결과*.xlsx`는 읽기만 하며 새 ERP 조회를 실행하지 않습니다.

회전은 **백업 후 원본 90도 회전 저장**입니다. 직접 압축과 달리 마지막 회전은 되돌리기 대상입니다. JPEG 회전은 다시 인코딩하므로 무손실이 아닙니다. 기존 가공본 픽셀까지 동시에 회전하거나 압축하는 것은 아닙니다.

휴지통 이동은 일반/보완자료 폴더에만 제공합니다. 이 작업의 복구는 Windows 휴지통을 사용합니다. 실제 행사 원본을 앱에서 임의로 삭제하지 않습니다.

## 제거한 기능

0.3.0 화면에서 트레이싱, 상단 리사이즈와 별도 옵션 창, 보완자료 대상 강연회 선택, 현재 보완자료 대체 이동을 제거했습니다. 자동입력·보람ERP·종합통계·마감·보고서·카카오톡 수집기 제어·SmartPortal 연동도 없습니다. 기존 전체 RMS와 기존 서비스는 변경하지 않았습니다.

## 업데이트와 보호

상단 `업데이트 확인 → 업데이트 설치`를 사용합니다. 새로운 정식 Release의 실행 패키지가 게시되어야 업데이트 대상이 됩니다. 0.1.0 사용자는 최초 한 번 새 ZIP을 풀어야 합니다. 자세한 인증·백업·복구는 [업데이트 안내](UPDATE_GUIDE.md)에 있습니다.

동일 업무 폴더를 기존 RMS와 Lite 또는 다른 PC에서 동시에 수정하지 마세요. 로컬 잠금이 NAS의 모든 사용자를 막지는 못합니다. 설정은 `%LOCALAPPDATA%\BoramRMSLite`에 분리 저장합니다. 앱 설치 폴더 안에 신청서를 보관하지 마세요.

리네임·상태·회전의 백업과 변경 기록은 `.boramrms\lite-journal`에 남으며 원본처럼 보호해야 합니다. 직접 압축에는 새 백업을 만들지 않습니다. 외부에서 변경된 파일을 되돌리기가 무조건 덮어쓰지는 않습니다.

## 검증 범위

0.3.0 Release 빌드 경고 0, 오류 0. 합성 자료 기반 기능·업데이트·UI 회귀시험 58개 통과, 실패 0개를 확인했습니다. 배포 패키지의 TEST_SUMMARY.txt에 해당 빌드 결과가 포함됩니다. 실제 고객 신청서, NAS 장시간/동시 작업, 모든 모니터 DPI와 한글 조합, 실제 새 버전 설치부터 재실행까지 전체 경로에 대한 무조건적인 보장을 의미하지 않습니다.
